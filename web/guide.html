Installation and first use

This guide starts with a disconnected demo, then creates a separate workspace for your own records. You do not need a GitHub account, bank login, AI account or Supabase project to try the demo.

1. Download and extract

  • Open the public repository.
  • Select Code → Download ZIP.
  • On Windows, right-click the ZIP and choose Extract All. On macOS/Linux, extract it normally.
  • Open the extracted project folder. Run the files from this folder, not from inside the ZIP.
  • Install Python if you do not have it. Python 3.11 or 3.12 is recommended. The offline demo supports Python 3.9+. On Windows, include Python in PATH when offered.

Keep the whole folder together. web/, workspace/, intelligence/ and the launcher files are part of the application.

2. Try the demo

ComputerStart
WindowsDouble-click start-demo-windows.bat
macOSOpen Terminal in this folder and run sh start-demo-mac.command
LinuxRun sh start-demo-linux.sh
Any terminalRun python demo.py or python3 demo.py

The browser opens http://127.0.0.1:8051. The normal launcher starts the server in the background; you may close its launcher terminal after it reports success. For a visible development server, use python demo.py --foreground and keep that terminal open.

The blue Demo · fictional data bar identifies this workspace. It contains invented investments, payment accounts, savings, debt, plans, an invoice and about five years of history. It does not connect to a bank, AI provider, local model or cloud database. Company figures, prices, headlines and comparison rates in demo mode are examples, not current financial information.

Start with the screenshot walkthrough. Try account filters, historical graphs, price/date sorting, savings-rate comparisons and debt scenarios. Demo chat returns clearly labelled saved examples. To try a deterministic import, download the DEMO ONLY sample CSV from Setup & help and upload it on Import.

Stop, reopen or reset


python launch.py demo --command stop
python demo.py
python launch.py demo --command restart

On Windows, stop-demo-windows.bat stops this profile. If you used foreground mode, press Ctrl+C in its terminal.

To reset demo edits, first stop it, then run python demo.py --reset. The old demo is preserved in the ignored backups/ folder before a new sample dataset is created. This never resets the personal profile. An interrupted first setup or an old unmarked demo folder is also preserved rather than deleted.

If port 8051 is busy, use python demo.py --port 8053. Do not stop an unrelated application just to free a port.

3. Switch to your own data

  • In the demo, select Use my own data in the top bar, or open Setup & help.
  • Select Start my personal workspace.
  • Your browser opens the separate workspace at http://127.0.0.1:8052/#setup.
  • Check that the top bar says Personal · your local data.
  • The personal workspace starts empty. Sample balances, transactions, invoices, history, settings and connections are not carried over.

Alternatively, double-click start-personal-windows.bat, run the corresponding macOS/Linux launcher, or run python personal.py.

ProfileLocal folderDefault portInitial state
Demo.demo-runtime/8051Fictional data; external services blocked
Personal.personal-runtime/8052Empty; optional connections disabled

Returning to the demo does not merge it with personal data. Restarting personal mode preserves your records. There is deliberately no personal-data reset button in the demo launcher.

4. Install optional features

The basic demo uses Python's built-in libraries. Live prices, AI authentication, Excel/PDF processing, encrypted-backup support and optional tray features use packages listed in requirements.txt.

  • Stop the personal workspace if it is running.
  • From the extracted project folder, run python install.py (python3 install.py on macOS/Linux), or double-click install-optional-windows.bat.
  • This creates .venv/ in this project and installs its dependencies. It does not install OpenBB or connect any accounts.
  • Start personal.py again. The launcher uses this virtual environment automatically.

You can also install manually with python -m venv .venv, activate it, then run python -m pip install -r requirements.txt. Run commands in the same Python environment used to start the dashboard.

5. Choose your connections

In personal mode, open Setup & help. Enable only what you want:

  • Live public data: quotes, company research, public filings where configured, and flexible-savings comparisons.
  • AI: your configured Claude, eligible ChatGPT-plan connection, or local model.
  • Supabase: your separately configured cloud copy.

Select Save choices & restart this workspace. After restart, configure the relevant provider in Settings. A choice enables the feature; it does not sign in, create a financial account, buy anything or copy someone else's credentials. If the browser reloads before restart finishes, wait a few seconds and refresh.

Use the account/key checklist first, or paste the setup-assistant prompt into ChatGPT/Claude for help. Follow Connections for exact instructions, costs, data sharing and limitations. Every connection is optional. The public app has no developer-supplied keys and no shared financial database.

6. Import real records

Do this in personal mode:

  • Begin with a recent bank export in CSV/TXT format where supported. Check its account, currency and date range.
  • Recognised bank CSVs apply immediately and return a summary with Undo. Check imported totals, duplicates and internal transfers. For flows that offer a preview, inspect it before applying.
  • Import current broker holdings and a complete execution/export history. Supported Trade Republic CSVs are calculated deterministically; other statements or screenshots may need AI.
  • Upload invoices or receipts to clarify the products behind existing bank payments. An invoice is evidence, not a second payment. Confirm matching and allocation in Receipts.
  • Enter confirmed flexible-savings balances/rates and debt terms. Leave unknown information empty rather than guessing.
  • Review account links, investment regions, savings-plan schedules and the review inbox.
  • Use Undo if an applied import or chat edit is wrong.

No direct ABN AMRO, DEGIRO, Raisin or Trade Republic account-login connector is bundled. Bank/broker exports and documents provide your private records. Public quote/rate sources are separate from account access. The dashboard is EUR-based; verify conversions and imported financial totals.

Return metrics need dated values and complete external cash flows. Missing execution, deposit, withdrawal, fee or FX evidence can leave a metric unavailable. Do not mark coverage complete merely to make a number appear.

7. Backups and sharing

Before a major update or moving computers, use Settings → Backups. Choose a portable password-protected backup and keep the password separately. Test its restore preview. Some optional cryptographic features require the installed packages.

The personal runtime contains your records, statements, cache, settings and credentials. It is Git-ignored. Financial backups can contain settings/keys; treat them as private. OpenAI refresh credentials are not part of a financial backup, so sign in again after moving computers. Windows-protected credentials/local backup keys may not work under another Windows account; use portable backups for migration.

Share this repository, its Download ZIP link or the screenshot guide. Never share .personal-runtime/, real exports, attachments, local settings, credentials, logs or financial backups. Nothing in the demo requires publishing your own data.

8. Update the application

Git checkout: stop the relevant profile, run git pull --ff-only, then restart its launcher. The launcher copies updated code into the runtime while preserving personal records. If Git reports local code changes, review them; do not force-reset your work.

ZIP installation: stop the profile, make a portable backup, and extract the new ZIP beside the old folder. Start a fresh personal workspace in the new folder and restore your verified backup using the documented restore workflow, or carefully keep the old hidden personal folder when replacing code in place. Do not overwrite personal runtime files with demo fixtures. Keep the old folder until you have verified the new copy.

After updating, press Ctrl+F5 once in the browser to reload scripts and styles. Existing demo edits remain; resetting the demo is optional and preserves a backup. Older installations containing personal files directly in the project root are not automatically migrated: back them up and import/restore confirmed records into the personal profile.

Start with the demo. You do not need to collect keys before trying it. In personal mode, local imports + public data + one chosen AI provider are a useful first setup. Supabase and advanced data providers can wait.

An API key is a secret that lets an application use a service. A project URL is the address of your database. Sign-in means completing the provider's browser login; you do not copy its tokens yourself.

Use the installation guide to download/start the app, connection instructions for each feature, and the setup-assistant prompt if you want ChatGPT or Claude to walk you through it.

Connections: what to enable and how

Use personal mode, install optional packages, then enable the relevant choice in Setup & help and restart. All connections start unconfigured. Nothing logs into a bank or shares records just because you downloaded the repository.

Start in this order

  • Personal workspace: follow Installation and check that no sample balances came across.
  • Your records: import a small bank/broker export and check totals. This needs no cloud database.
  • Public data: enable it for prices and savings comparisons; it does not need a default API key.
  • One AI route: choose Claude Code, ChatGPT-plan sign-in or Anthropic API. Use the account you already have when supported.
  • SEC, if wanted: configure identification only after you agree to send that contact to SEC.
  • Cloud/advanced sources, if wanted: add Supabase, Ollama, OpenBB or Quiver independently. Missing an optional provider should not prevent ordinary local use.

Keep the complete account/key checklist beside you. The copyable setup-assistant prompt lets ChatGPT or Claude guide these steps. Nothing in this guide supplies a shared key or guarantees a provider subscription.

Bank and broker records

In your bank/broker application, export statements or transaction/execution CSVs. In the dashboard, open Import, upload and review the returned totals. Recognised bank CSVs apply directly with Undo; inspect a preview before applying when that workflow offers one. Start with current balances/holdings, then add history. Supported CSV formats can work without AI; screenshots, PDFs and unrecognised layouts may require a chosen importer.

Bank exports containing PayPal debits do not identify every purchased product. PayPal exports and invoices can add evidence; confirm matching to avoid double-counting. The dashboard does not store a bank password or place orders. Savings plans are dashboard records, not instructions to a broker.

Live market and savings information

Enable Live public data, restart, then use Investments/Explore and Savings & debt → Rates & options. The savings view loads source-dated flexible-EUR products, separates promotions, applies published amount limits and retains stale markers when a source fails. It does not replace a saved personal rate or establish your eligibility. A published overnight account may still require transfer time. Protection limits belong to the legal bank and retain their quoted currency.

Public requests concern securities/products, not your account balances. There is no guarantee of complete market coverage or a real-time quote. Inspect source/retrieval/effective dates and product terms before acting. Ordinary daily price charts are separate from adjusted historical-return series.

Claude Code: use your own CLI login

  • Install Claude Code using the current official setup guide. A native Windows option is winget install Anthropic.ClaudeCode; macOS/Linux instructions are on that page.
  • Open a new terminal and run claude --version, then claude to complete your own login.
  • Enable AI in personal Setup and restart the dashboard.
  • In Settings → Claude & AI, check the connection and choose Claude for chat/import. The small chat and import provider switches can also change it per workflow.
  • Ask a small question first. Check the chosen account/context and provider's limits.

After login, restart the personal dashboard so it can detect the CLI. A Claude desktop/web login alone is not proof that the command-line program is installed and signed in. If Settings still reports disconnected, run claude --version in a new terminal, verify your login with claude, then restart the dashboard. See the official CLI quickstart.

Anthropic API: an alternative to CLI login

  • Open your own Claude Console account.
  • Choose Settings → API keys → Create key, name it for this dashboard and choose its scope/expiration.
  • Check the Console's credit/billing balance and usage limits before making API requests. An API route uses Console credits/billing; do not assume a Claude chat subscription provides unlimited API usage. Some eligible plans can claim API credits in a linked Console organization.
  • In the personal dashboard, open Settings → Claude & AI → API key. Paste your own key there and select Save. Do not use an organization Admin API key.
  • Choose Claude for chat/import, try a small request and verify usage in your own Console. The saved key takes precedence over the CLI route; saving an empty key removes the local saved key. Check any independently configured environment key if it still appears connected.

See API-key authentication and eligible plan credits. This is optional: a working chosen Claude Code route does not require manually copying an API key. Do not paste keys into chat, commit them or place them in the public sample files. AI chat/import sends the selected question/document/context to your configured provider. Explicitly requested supported dashboard edits have Undo; they never place broker orders.

OpenAI / ChatGPT plan

  • Enable AI in personal Setup & help, save/restart, and open Settings → Claude & AI.
  • Find ChatGPT plan and select Connect. The chat/import OpenAI controls can also offer Continue with ChatGPT.
  • Complete the OpenAI browser login and consent yourself. Return to the local dashboard; leave it running while the local callback completes.
  • Verify that the plan connection shows connected. Choose OpenAI for Chat with and/or Read imports with, then Save choices.
  • Under OpenAI models, choose an available chat/import model or keep the account default. The small chat and Import switches can change the provider for those workflows.
  • Try a short question and check Usage. A connected identity or model list alone is not proof that your account can run that request.

This is a ChatGPT-plan sign-in route, not the API-key route. Eligible Plus/Pro accounts can use plan access where the provider permits it; workspace policies, models and preview limits still apply. The app does not silently switch to paid OpenAI API billing. Do not generate or purchase an OpenAI API key for this feature. See the official sign-in quickstart and preview limitations.

If sign-in opens but does not finish, confirm the local app is running, complete the browser consent, and retry from the same profile. If a request is refused, keep the exact error with tokens/identifiers removed. Reconnect or choose another available model; eligibility failures may require a different supported provider chosen by you.

Use your own account, not the author's login or a shared token. You can disconnect it in Settings. Windows credentials use local OS protection; on other systems keep credential files and their containing folder private. Signing in does not grant this dashboard access to your ChatGPT conversation history.

Ollama

  • Install Ollama and start its local service.
  • Follow the official quickstart to download/run a local model suitable for your hardware. A cloud model is a different choice and should not be described as local processing.
  • Confirm a model appears with ollama list. Model downloads use disk space and an internet connection; inference needs suitable memory/compute.
  • Enable AI in personal Setup, restart, then select the model under Settings' local-AI controls.
  • Test a small supported categorisation/classification task and check the result.

The included adapter expects Ollama on http://127.0.0.1:11434. In Settings, select a local model for small tasks. This is not a substitute for a live research source or a guarantee that chat/import supports every local model. Check classifications and extracted figures. Local-model availability can be seen in Settings; the demo never discovers or uses your local model automatically.

SEC EDGAR and research coverage

  • Enable public data in personal mode.
  • In Settings → Public data / Connections, enter the contact identification SEC requires.
  • Explicitly allow that identifying contact email to be sent with SEC requests.
  • Refresh research and inspect filing/report dates and coverage.

SEC data is disclosure data: institutional holdings are delayed, insider forms need classification, and non-US coverage can be missing. Absence of a record is not proof that no event occurred. Read INTELLIGENCE.md for sources and calculation conventions. Public ECB, OECD, BIS, AFM and other adapters need no private-bank login; optional providers may need their own account.

Supabase cloud copy

Local use does not require Supabase. If you choose it, the configured portfolio/history/payment/receipt metadata is copied to your own hosted project; raw local source files are not automatically made public.

Create your own project

  • Open Supabase Dashboard, sign in and create a dedicated empty project for your own dashboard. Complete any project/plan/terms decisions yourself.
  • Choose your organization, a clear project name and an appropriate region. Keep any database password in your own password manager; this application uses its REST interface and does not ask for that password.
  • Wait for the project to finish provisioning. Do not reuse a production database from another application.

Create the tables before connecting

Open SQL Editor → New query in that project. In your extracted application folder, open each file as text, copy its full contents into a query, run it, and check for a successful result before continuing. Use this order:

OrderRepository fileCreates
1supabase-schema.sqlCore accounts, institutions, holdings, instruments, history and portfolio backup
2supabase-history.sqlRecorded account history and yearly flows
3supabase-spending.sqlPayment accounts, categories, rules and transactions
4supabase-plans.sqlRecurring investment plans and payment linking fields
5supabase-receipts.sqlInvoice/product metadata and evidence links

These are fresh-install scripts for this app's schema, not general migrations for an arbitrary existing database. They contain no destructive DROP TABLE commands. Keep RLS enabled; the views use the caller's security context and no public read policies are supplied. Do not add anonymous/public read policies just to fix an incorrect key.

Find the two values the dashboard needs

  • In your project's Connect dialog, find the Project URL, shaped like https://YOUR_PROJECT_REF.supabase.co. This is not the dashboard page address and not a PostgreSQL connection string.
  • In Settings → API Keys, find or create a dedicated server secret key, beginning sb_secret_. Prefer this modern key for a new project. An existing legacy service_role key is a supported alternative while available; a publishable/anon key cannot perform this app's backend copy.
  • Keep the secret private. It has elevated database access and bypasses RLS. Do not send it to a setup assistant, commit it, embed it in frontend code, or share its screenshot. Only your own local Python backend uses the key saved through the local form. Official key documentation.

Connect and verify the first copy

  • In personal Setup & help, enable Supabase, then save/restart. Enabling it alone does not create a connection.
  • Open Settings → Data → Cloud copy → Set up.
  • Enter your Project URL and Secret key yourself in the local form.
  • Select Connect and sync only when you are ready to send the intended portfolio/history/payment/receipt metadata to your own project. This button tests access, saves the local configuration and starts the first copy; it is not a read-only test button.
  • Inspect the sync result, then open your own Supabase Table Editor. Verify the expected accounts, holdings and payments, and check receipt metadata where present. No rows on an empty personal workspace can be a correct result.
  • Later, Sync now requests another copy; automatic copying requires the app to remain running. Disconnect stops use of the saved connection but leaves the existing cloud rows in place.

This is a local-to-cloud copy, not a bank connector and not automatic two-way editing/restore. The spending sync replaces the dashboard's spending tables in that project; this is another reason to use a dedicated project. Local source documents are not uploaded as cloud file storage by this metadata sync.

OpenBB, Quiver and other optional sources

Most public features use the built-in sources. OpenBB is optional and is not installed by the basic installer. It is not preinstalled for the person downloading this repository.

OpenBB: advanced, optional

Start the personal profile once so its folder exists. Use Python 3.10+ (3.11/3.12 recommended) and install the repository's v4 compatibility requirements in the private personal runtime. From the project folder, the Windows commands are:


python -m venv .personal-runtime/.openbb-env
.\.personal-runtime\.openbb-env\Scripts\python.exe -m pip install -r requirements-openbb.txt

On macOS/Linux:


python3 -m venv .personal-runtime/.openbb-env
.personal-runtime/.openbb-env/bin/python -m pip install -r requirements-openbb.txt

The adapter detects that runtime-local environment. Restart the personal app and check Data connections & coverage → OpenBB. The supplied adapter uses a v4-compatible layout; upgrading major versions can require code/configuration changes. Try supported public data first; additional providers have their own entitlements and private settings. No author credentials are installed.

Follow INTELLIGENCE.md and requirements-openbb.txt, use a separate OpenBB environment, and configure its Python/provider path in Connections. Provider entitlements and returned datasets vary; missing data remains unavailable.

Quiver: advanced, optional

Open Quiver API setup, sign into your own account and check that your entitlement covers the datasets you want. Obtain your own token, enable public data in personal mode, then use Data connections & coverage → Quiver API key and Save connections. Refresh a supported dataset and inspect its source/coverage or failure. A saved key is not proof of entitlement.

For Quiver, add your own key in Settings only if your subscription supplies the desired dataset. It is not necessary for the core dashboard. You can remove optional keys without losing your local financial records.

Other built-in public sources: no extra key checklist

The current adapters include selected ECB, Eurostat/CBS, World Bank, OECD, BIS, FRED chart CSV, AFM disclosures, GLEIF, OpenFIGI identifier candidates, GDELT, openFDA, ClinicalTrials.gov, USAspending and Kraken public-market history. Use public-data mode and the supported query controls in Connections/research tools. Coverage and public rate limits vary; an available adapter is not a promise that every query succeeds.

You do not need a separate key for each of these included public adapters. The FRED adapter uses selected public CSV downloads, not every keyed FRED API function. Kraken public candles do not use your exchange account or permit trading. OpenFIGI returns identifier candidates for review, not proof that a security match is correct. None of these connects to your bank or uploads your ledger as a public-data search query.

GitHub and updates

GitHub distributes the code, not your finances. Downloading a ZIP requires no Git login. Cloning/pulling requires Git; a private fork requires your own GitHub authentication. Keep runtime folders ignored. Source-update checks do not upload your local finances. Read the installation update steps before replacing code.

Backups and moving computers
